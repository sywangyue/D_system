## Design System

| Property | Value | Source |

## Spacing Scale

Declared values (multiples of 4 only):

| Token | px Value | Tailwind Class | Usage |
|-------|----------|----------------|-------|
| xs | 4px | p-1 / gap-1 | Icon gaps, pill internal vertical padding, badge padding |
| sm | 8px | p-2 / gap-2 | Pill internal horizontal padding, compact element spacing |
| md | 16px | p-4 / gap-4 | Card internal padding, default element spacing |
| lg | 24px | p-6 / gap-6 | Section padding, between filter rows, between KPI cards |
| xl | 32px | p-8 / gap-8 | Main content area top/bottom padding |
| 2xl | 48px | p-12 / gap-12 | Major section breaks (filters → KPI area) |
| 3xl | 64px | p-16 / gap-16 | Page-level vertical rhythm (not commonly used) |

Exceptions:
- Sidebar navigation item height: 44px (touch-target minimum, enforced via `min-h-[44px]`)
- Sidebar width: 220px fixed (not on scale — structural constant)
- KPI card highlight number: display size at 36px (see Typography)
- Filter pill height: 32px (`h-8`) — chosen for information density on data dashboard

## Interaction Contracts

### Filter Tab Cascading Behavior

```
1. Row 1 (industry_l1) — single-select:
   - On select: set industry_l1 state, clear industry_l2 state,
     fetch available industry_l2 options for selected l1 from API.
   - Show Row 1b (industry_l2 sub-pills) only when industry_l1 is selected.
   - Row 1b: same pill style, single-select.
   - Deselecting industry_l1 (clicking selected pill again): allowed,
     clears both l1 and l2, hides Row 1b.

2. Row 2 (competition_relation) — multi-select:
   - "全部" is exclusive: selecting it deselects others.
   - Selecting any specific option deselects "全部".
   - No option selected = same as "全部" (API receives no relation param).
   - Default on load: "全部" selected.

3. Row 3 (mds_related) — single-select:
   - Default on load: "全部" selected.
   - Clicking selected pill again: no-op (must have a selection).

4. Debounce: all filter changes trigger API call after 300ms debounce.
   In-flight requests are cancelled (use AbortController).

5. Loading state: KPI cards show skeleton (animate-pulse gray bg) during fetch.
   Pie chart shows loading spinner centered in its container.
```

### Authentication Flow

```
1. Unauthenticated access to any route except /login:
   → Next.js middleware redirects to /login (per Pattern 1 in 04-RESEARCH.md)

2. Successful login:
   → Supabase Auth sets session cookie
   → Redirect to /dashboard

3. Session expiry:
   → middleware.ts detects expired session, redirects to /login
   → /login page shows no error (silent redirect)

4. Role enforcement:
   - /setting route: middleware checks app_metadata.role === 'admin'
     If not admin, redirect to /dashboard
   - Sidebar: Setting item conditionally rendered client-side based on role
     (both middleware server-guard AND client UI guard)

5. Logout:
   → supabase.auth.signOut() called
   → redirect to /login
   → Sidebar shows 退出 button (text-sm text-gray-600, lucide LogOut icon)
```

### Map Interaction

```
1. Default state: map loads with all city clusters visible.
2. City marker click: Leaflet Popup opens showing city name + exhibition count.
3. Map controls: zoom in/out (leaflet default), no custom controls needed.
4. No filter integration in Phase 4 — map shows all exhibitions globally.
   (Filter integration is deferred / not in Phase 4 scope)
```

### Calendar Interaction

```
1. Default view: month view, current month.
2. Month/week toggle: top-right of calendar card.
3. Event click: opens ExhibitionDetailModal (see Component Contracts above).
4. Navigation (prev/next month or week): react-big-calendar built-in toolbar,
   styled to match design system (pills replacing default buttons).
5. Events are fetched on mount; no real-time filter cascade with Dashboard.
```
